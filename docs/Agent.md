## 1. Golden Rules — Non-Negotiable

> [!CAUTION]
> Violating ANY of these rules will cause production data corruption, ZATCA audit failures, or Saudi PDPL legal violations. No exceptions.

| # | Rule | Consequence of Violation |
|---|------|--------------------------|
| GR-1 | **ZERO floating-point for SAR amounts.** Use `Decimal(12,4)` in Postgres, `decimal.js` in TypeScript. NEVER `number` for money. | Financial rounding errors. ZATCA invoice rejection. |
| GR-2 | **NEVER `DELETE` pricing rules, quotes, invoices, or BOMs.** These are legally auditable under ZATCA. Soft-delete or version-append only. | Tax audit failure. Legal liability. |
| GR-3 | **NEVER allow production cuts (`CuttingJob` → `NESTED`) without a confirmed `PaymentTransaction` for Milestone 1 (50% deposit).** | Irrecoverable material waste. 2440×1220mm sheets cannot be restocked. |
| GR-4 | **All Saudi phone numbers normalize to E.164 `+9665xxxxxxxx` before storage.** Use `normalizeSaudiPhone()` from `src/lib/validation/saudi-validators.ts`. | Duplicate accounts. OTP delivery failure. |
| GR-5 | **Customer PII (phone, email, National ID) is NEVER exposed on factory-floor displays.** Use `BOMItem.barcodeOpaqueToken` (UUID) instead. | Saudi PDPL violation. |
| GR-6 | **All `@updatedAt` fields are auto-managed by Prisma.** Never set them manually in `create` or `update` calls. | Silent timestamp corruption. |
| GR-7 | **Prisma Client must be a singleton.** Import from `src/lib/prisma.ts`. Never instantiate `new PrismaClient()` in application code. | Connection pool exhaustion during Next.js hot-reload. |
| GR-8 | **15.0000% VAT is exact.** Always read `PricingRule.vatPercentage` from the database, never hardcode `0.15`. | Tax miscalculation if rate changes. |

## 4. Schema Modification Guidelines

### 4.1 Adding a New Model

Follow this exact sequence:

1. **Plan** — Identify the table's domain module from `Architecture.md` (Hexagonal Modular Monolith)
2. **Name** — Use PascalCase singular for models (`MaterialSheet`, not `material_sheets`)
3. **Map** — ALWAYS add `@@map("snake_case_plural")` to match PostgreSQL convention
4. **Fields** — Follow these field conventions:

```prisma
model NewEntity {
  // 1. Primary key — ALWAYS UUID
  id        String   @id @default(uuid()) @db.Uuid

  // 2. Foreign keys
  orderId   String   @map("order_id") @db.Uuid

  // 3. Business fields (map to snake_case)
  nameAr    String   @map("name_ar") @db.VarChar(255)
  nameEn    String   @map("name_en") @db.VarChar(255)

  // 4. Bilingual fields — ALWAYS provide both ar/en

  // 5. SAR monetary fields — ALWAYS Decimal(12,4)
  amountSar Decimal  @map("amount_sar") @db.Decimal(12, 4)

  // 6. Boolean flags
  isActive  Boolean  @default(true) @map("is_active")

  // 7. Timestamps — ALWAYS last
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(6)
  updatedAt DateTime @updatedAt @map("updated_at") @db.Timestamptz(6)

  // 8. Relations
  order     Order    @relation(fields: [orderId], references: [id], onDelete: Restrict)

  // 9. Indexes
  @@index([orderId])
  @@map("new_entities")
}
```

### 4.2 Field Naming Conventions

| TypeScript (camelCase) | PostgreSQL (snake_case via `@map`) | Example |
|------------------------|-------------------------------------|---------|
| `fullName` | `full_name` | `@map("full_name")` |
| `vatAmountSar` | `vat_amount_sar` | `@map("vat_amount_sar")` |
| `createdAt` | `created_at` | `@map("created_at")` |
| `isActive` | `is_active` | `@map("is_active")` |

### 4.3 Adding a New Enum

```prisma
enum NewStatus {
  ACTIVE
  SUSPENDED
  ARCHIVED
}
```

**Rules:**
- Enum values are UPPER_SNAKE_CASE
- Group enums at the top of `schema.prisma`, before models
- Each new enum needs a migration (it creates a PostgreSQL `CREATE TYPE`)

### 4.4 Adding Relations

| Relation Type | Prisma Pattern | `onDelete` Rule |
|--------------|----------------|-----------------|
| Belongs-to (required FK) | `@relation(fields: [...], references: [id], onDelete: Restrict)` | `Restrict` for domain data |
| Belongs-to (optional FK) | `@relation(fields: [...], references: [id], onDelete: SetNull)` | `SetNull` for optional refs |
| Has-many (cascade child) | `children ChildModel[]` | `Cascade` on the child side |
| 1:1 required | `profile Profile?` ↔ `@@unique([userId])` | `Cascade` |

> [!IMPORTANT]
> **Never use `onDelete: Cascade` on financially significant relations** (Order → PricingRule, Invoice → Company, PaymentTransaction → Order). Use `Restrict` to prevent orphaned financial records.

### 4.5 Pre-Flight Checklist Before Modifying Schema

- [ ] Does this table exist in `Database.md` or `src/database-schema.md`? If not, add it there first.
- [ ] Are bilingual fields (ar/en) provided where user-facing?
- [ ] Are monetary fields using `@db.Decimal(12, 4)` (not Float, not Int)?
- [ ] Does the `@@map()` follow `snake_case_plural`?
- [ ] Are all FK fields indexed with `@@index([])`?
- [ ] Is `@db.Timestamptz(6)` used for all date/time fields (Saudi timezone: `Asia/Jeddah` UTC+3)?
- [ ] Are string fields capped with `@db.VarChar(N)` for known-length data?

## 5. Migration Workflow

### 5.1 Development Migration

```bash
# Step 1: Edit prisma/schema.prisma

# Step 2: Validate the schema (catches syntax errors, relation issues)
npx prisma validate

# Step 3: Create the migration (naming convention below)
npx prisma migrate dev --name <migration_name>

# Step 4: Regenerate the Prisma Client
npx prisma generate

# Step 5: Run tests to verify nothing broke
npm test
```

### 5.2 Migration Naming Convention

Format: `YYYYMMDD_<verb>_<entity>_<detail>`

| Migration Name | When to Use |
|---------------|-------------|
| `20261126_create_coupon_table` | Adding a new table |
| `20261126_add_risk_score_to_customer_profile` | Adding a column |
| `20261126_create_idx_orders_status_created` | Adding an index |
| `20261126_alter_payment_add_refund_fields` | Modifying existing table |
| `20261126_seed_default_categories` | Data migration (seed in SQL) |

### 5.3 Production Migration

```bash
# NEVER run `prisma migrate dev` in production
# Use deploy command instead:
npx prisma migrate deploy
```

> [!WARNING]
> `prisma migrate dev` will reset the database if it detects drift. ALWAYS use `prisma migrate deploy` for staging/production.

### 5.4 Resetting Development Database

```bash
# Full reset — drops all tables, re-runs all migrations, re-seeds
npx prisma migrate reset

# This runs:
# 1. Drop schema
# 2. Create schema
# 3. Apply all migrations
# 4. Run seed.ts
```

### 5.5 Handling Migration Conflicts

If two developers create migrations simultaneously:

1. `git pull` to get the other migration
2. `npx prisma migrate dev` — Prisma will detect and merge
3. If conflict is unresolvable: `npx prisma migrate resolve --applied <name>`

### 6.1 Seed File Location

```

```

Executed via:
```bash
npx tsx prisma/seed.ts
# OR
npm run db:seed
```

### 6.2 Seed Execution Order (FK Dependencies)

The seed must follow this exact order due to foreign key constraints:

```
1. Company        ← No dependencies
2. Users          ← Requires Company
3. Categories     ← No dependencies
4. MaterialSheet  ← No dependencies
5. HardwareItem   ← No dependencies
6. EdgeBanding    ← No dependencies
7. ProductTemplate ← Requires Category
8. TemplateHardwareMap ← Requires ProductTemplate + HardwareItem
9. PricingRule    ← Requires Company + User (createdBy)
```

### 6.3 Idempotent Seeding with `upsert`

**ALWAYS use `upsert` for seed data:**

```typescript
const entity = await prisma.entity.upsert({
  where: { uniqueField: 'known-value' },  // Use natural unique key
  update: {},                               // No-op on re-run
  create: { /* full entity data */ },
});
```

**Exception:** `PricingRule` uses `create` (not upsert) because pricing rules are append-only versioned records. Each seed run creates a new version.

### 6.4 Seed Data Integrity Rules

- **Company:** CR Number `1010884920`, VAT Number `310294857200003` (real SATCO mock)
- **Admin Phone:** `+966500000001` (E.164 normalized)
- **Material Sheets:** Egger standard 2440×1220mm dimensions
- **VAT:** Always `15.0000` exactly (4 decimal places)
- **Currencies:** Always `SAR` (Saudi Riyal, ISO 4217)

## 7. Query Patterns & Best Practices

### 7.1 Select vs Include

```typescript
// ✅ GOOD — Select only needed fields (reduces payload)
const orders = await prisma.order.findMany({
  select: {
    id: true,
    orderNumber: true,
    status: true,
    grandTotalSar: true,
    customer: {
      select: {
        fullName: true,
        phone: true,  // ⚠️ OK in admin context, NEVER on factory floor
      },
    },
  },
});

// ✅ GOOD — Include full relation when needed
const orderWithItems = await prisma.order.findUnique({
  where: { id: orderId },
  include: {
    items: {
      include: {
        template: true,
        bomItems: true,
      },
    },
    timeline: { orderBy: { createdAt: 'desc' } },
    payments: true,
  },
});

// ❌ BAD — Never mix select and include at the same level
// prisma.order.findMany({ select: { id: true }, include: { items: true } });
```

### 7.2 Cursor-Based Pagination (Recommended)

```typescript
// For infinite scroll / "Load More" (preferred for SATCO customer-facing)
async function getOrders(cursor?: string, take = 20) {
  return prisma.order.findMany({
    take: take + 1, // Fetch one extra to detect "hasMore"
    ...(cursor && {
      skip: 1,
      cursor: { id: cursor },
    }),
    orderBy: { createdAt: 'desc' },
    select: {
      id: true,
      orderNumber: true,
      status: true,
      grandTotalSar: true,
      createdAt: true,
    },
  });
}
```

### 7.3 Offset Pagination (Admin Dashboard Only)

```typescript
// For admin tables with page numbers
async function getOrdersPage(page: number, pageSize = 25) {
  const [orders, total] = await Promise.all([
    prisma.order.findMany({
      skip: (page - 1) * pageSize,
      take: pageSize,
      orderBy: { createdAt: 'desc' },
    }),
    prisma.order.count(),
  ]);

  return {
    data: orders,
    pagination: {
      page,
      pageSize,
      totalPages: Math.ceil(total / pageSize),
      totalRecords: total,
    },
  };
}
```

### 7.4 Filtered Queries with Dynamic Conditions

```typescript
// Build where clause dynamically for search/filter
function buildOrderFilter(filters: {
  status?: OrderStatus;
  customerId?: string;
  dateFrom?: Date;
  dateTo?: Date;
  search?: string;
}) {
  const where: Prisma.OrderWhereInput = {};

  if (filters.status) where.status = filters.status;
  if (filters.customerId) where.customerId = filters.customerId;
  if (filters.dateFrom || filters.dateTo) {
    where.createdAt = {
      ...(filters.dateFrom && { gte: filters.dateFrom }),
      ...(filters.dateTo && { lte: filters.dateTo }),
    };
  }
  if (filters.search) {
    where.orderNumber = { contains: filters.search, mode: 'insensitive' };
  }

  return where;
}
```

### 7.5 Aggregation Queries

```typescript
// Revenue dashboard
const revenue = await prisma.order.aggregate({
  where: { status: { not: 'CANCELLED' } },
  _sum: { grandTotalSar: true, paidAmountSar: true },
  _count: { id: true },
  _avg: { grandTotalSar: true },
});

// Group by status
const statusBreakdown = await prisma.order.groupBy({
  by: ['status'],
  _count: { id: true },
  _sum: { grandTotalSar: true },
  orderBy: { _count: { id: 'desc' } },

```

### 7.6 Raw SQL (Escape Hatch — Use Sparingly)

```typescript
// Only for complex CTEs, window functions, or performance-critical reports
const result = await prisma.$queryRaw<{ month: string; total: Decimal }[]>`
  SELECT
    TO_CHAR(created_at, 'YYYY-MM') AS month,
    SUM(grand_total_sar) AS total
  FROM orders
  WHERE status != 'CANCELLED'
  GROUP BY month
  ORDER BY month DESC
  LIMIT 12
`;
```

> [!NOTE]
> When using `$queryRaw`, column names come back as PostgreSQL snake_case. Map them to camelCase in your TypeScript code.

## 8. Financial Field Handling — SAR Currency

### 8.1 The Iron Rule

| Layer | Type | Precision |
|-------|------|-----------|
| PostgreSQL | `DECIMAL(12, 4)` | 12 digits, 4 fractional (max: 99,999,999.9999 SAR) |
| Prisma Schema | `@db.Decimal(12, 4)` | Prisma returns `Prisma.Decimal` (string-based) |
| TypeScript | `Decimal` from `decimal.js` | 28-digit precision, `ROUND_HALF_UP` |
| API Response | `string` | Always return monetary values as strings: `"1250.5000"` |
| Display | `string` | 2 decimal places for UI: `"1,250.50 SAR"` |

### 8.2 Converting Prisma Decimal to decimal.js

```typescript
import { toDecimal, formatSar, formatSarLedger } from '@/lib/decimal';

// Prisma returns Prisma.Decimal (string-like)
const order = await prisma.order.findUnique({ where: { id } });

// Convert to decimal.js for calculations
const grandTotal = toDecimal(order!.grandTotalSar.toString());
const paidAmount = toDecimal(order!.paidAmountSar.toString());
const dueAmount = grandTotal.minus(paidAmount);

// Format for display
const displayPrice = formatSar(grandTotal, true);  // "1250.50 SAR"

// Format for database storage
const ledgerValue = formatSarLedger(dueAmount);     // "750.5000"
```

### 8.3 Storing Calculated Amounts

```typescript
// ✅ CORRECT — toFixed(4) string for Prisma Decimal fields
await prisma.order.update({
  where: { id: orderId },
  data: {
    vatAmountSar: vatAmount.toFixed(4),         // "187.5000"
    grandTotalSar: grandTotal.toFixed(4),       // "1437.5000"
    paidAmountSar: paidAmount.toFixed(4),       // "718.7500"
    dueAmountSar: dueAmount.toFixed(4),         // "718.7500"
  },
});

// ❌ WRONG — Never pass raw number
// data: { grandTotalSar: 1437.50 }  // JavaScript float = imprecise
```

### 8.4 Milestone Payment Calculation

```typescript
import { calculateMilestones } from '@/lib/decimal';

const { milestone1Deposit, milestone2PreDispatch, milestone3Handover } =
  calculateMilestones(order.grandTotalSar.toString());

// M1: 50% → Round to 2dp
// M2: 40% → Round to 2dp
// M3: 10% → Remainder (Grand - M1 - M2) for zero-penny guarantee
```

### 8.5 VAT Calculation

```typescript
import { calculateZatcaVat, calculateGrandTotal } from '@/lib/decimal';

// Read VAT rate from PricingRule (never hardcode)
const pricingRule = await prisma.pricingRule.findFirst({
  where: {
    companyId: satcoCompanyId,
    effectiveFrom: { lte: new Date() },
    OR: [
      { effectiveTo: null },
      { effectiveTo: { gte: new Date() } },
    ],
  },
  orderBy: { effectiveFrom: 'desc' },
});

const vatRate = pricingRule!.vatPercentage;  // 15.0000
const vatAmount = calculateZatcaVat(netSubtotal, vatRate.toString());
const grandTotal = calculateGrandTotal(netSubtotal, vatAmount);
```

## 9. Saudi-Specific Validation Rules

### 9.1 Phone Numbers

```typescript
import { normalizeSaudiPhone, SaudiPhoneSchema } from '@/lib/validation/saudi-validators';

// Before storing in User.phone:
```

### 9.4 Validation Before Database Write

**Pattern: Validate → Normalize → Write**

```typescript
async function createCustomer(input: unknown) {
  // 1. Validate with Zod
  const validated = CreateCustomerSchema.parse(input);

  // 2. Normalize
  const phone = normalizeSaudiPhone(validated.phone);

  // 3. Check blacklist
  const blacklisted = await prisma.blacklistEntry.findUnique({
    where: { phone },
  });
  if (blacklisted) {
    throw new DomainRuleError('BLACKLISTED_PHONE', 'This phone is blacklisted');
  }

  // 4. Atomic write
  return prisma.$transaction(async (tx) => {
    const user = await tx.user.create({
      data: {
        phone,
        fullName: validated.fullName,
        email: validated.email,
        role: 'CUSTOMER',
      },
    });

    await tx.customerProfile.create({
      data: {
        userId: user.id,
        city: validated.city ?? 'Jeddah',
      },
    });

    return user;
  });
}
```

## 10. Index Optimization Guidelines

### 10.1 Current Index Map (25 Tables)

The schema already includes these indexes. When adding new ones, follow these rules:

| Index Type | When to Add | Example |
|-----------|-------------|---------|
| **Single Column** | FK columns, frequently filtered fields | `@@index([customerId])` |
| **Composite** | Multi-column WHERE or ORDER BY | `@@index([customerId, status])` |
| **Unique** | Natural keys, business identifiers | `@unique` on `crNumber`, `orderNumber`, `sku` |
| **Partial** (via raw SQL) | Large tables where only subset is queried | `WHERE status = 'ACTIVE'` |

### 10.2 Index Rules for SATCO

1. **Every FK field gets an `@@index`** — Prisma does NOT auto-index FKs
2. **Every `@unique` field is auto-indexed** — No need for separate `@@index`
3. **Composite indexes follow query patterns:**
   - `orders: @@index([customerId, status])` — "My orders" page filtered by status
   - `orders: @@index([createdAt])` — Dashboard date range queries
   - `installation_jobs: @@index([scheduledDate])` — Technician daily schedule

### 10.3 When NOT to Add Indexes

- Tables with <1000 rows (Categories, PricingRules) — overhead > benefit
- Columns used only in `SELECT` (not `WHERE`/`ORDER BY`/`JOIN`)
- Very wide `Json` columns (`configurationJson`, `cuttingPatternJson`)

### 10.4 Adding Indexes via Migration

```prisma
// In schema.prisma — add to model block
@@index([newColumn])
@@index([col1, col2])  // composite

// Then:
// npx prisma migrate dev --name 20261126_add_idx_table_column
```

```typescript
      dueAmountSar: grandTotal.toFixed(4),
    },
  });

  // 2. Create order items
  for (const item of cartItems) {
    await tx.orderItem.create({
      data: {
        orderId: newOrder.id,
        templateId: item.templateId,
        configuredWidthMm: item.configuredWidthMm,
        configuredHeightMm: item.configuredHeightMm,
        configuredDepthMm: item.configuredDepthMm,
        configurationJson: item.configurationJson,
        quantity: item.quantity,
        unitPriceSar: item.unitPriceSar.toFixed(4),
        totalPriceSar: item.totalPriceSar.toFixed(4),
        itemVatSar: item.itemVatSar.toFixed(4),
      },
    });
  }

  // 3. Record timeline entry
  await tx.orderTimeline.create({
    data: {
      orderId: newOrder.id,
      fromStatus: null,
      toStatus: 'DRAFT',
      actionBy: 'system',
      notes: 'Order created from cart',
    },
  });

  // 4. Clear cart
  await tx.cartItem.deleteMany({ where: { cartId: cart.id } });
  await tx.cart.delete({ where: { id: cart.id } });

  return newOrder;
});
```

## 12. Order State Machine Transitions

### 12.1 Valid Transitions

```
DRAFT → PENDING_DEPOSIT
PENDING_DEPOSIT → PAID_DEPOSIT | CANCELLED
PAID_DEPOSIT → CONFIRMED | CANCELLED
CONFIRMED → PRODUCTION_QUEUED
PRODUCTION_QUEUED → IN_PRODUCTION
IN_PRODUCTION → QC_COMPLETED
QC_COMPLETED → DISPATCH_HOLD_DUE_PAYMENT | READY_FOR_DELIVERY
DISPATCH_HOLD_DUE_PAYMENT → READY_FOR_DELIVERY
READY_FOR_DELIVERY → OUT_FOR_DELIVERY
OUT_FOR_DELIVERY → DELIVERED
DELIVERED → INSTALLATION_SCHEDULED
INSTALLATION_SCHEDULED → INSTALLATION_IN_PROGRESS
INSTALLATION_IN_PROGRESS → HANDOVER_COMPLETED | REWORK (loop back)
HANDOVER_COMPLETED → (terminal)
CANCELLED → (terminal)
```

### 12.2 Transition Guard Pattern

```typescript
const VALID_TRANSITIONS: Record<OrderStatus, OrderStatus[]> = {
  DRAFT: ['PENDING_DEPOSIT'],
  PENDING_DEPOSIT: ['PAID_DEPOSIT', 'CANCELLED'],
  PAID_DEPOSIT: ['CONFIRMED', 'CANCELLED'],
  CONFIRMED: ['PRODUCTION_QUEUED'],
  PRODUCTION_QUEUED: ['IN_PRODUCTION'],
  IN_PRODUCTION: ['QC_COMPLETED'],
  QC_COMPLETED: ['DISPATCH_HOLD_DUE_PAYMENT', 'READY_FOR_DELIVERY'],
  DISPATCH_HOLD_DUE_PAYMENT: ['READY_FOR_DELIVERY'],
  READY_FOR_DELIVERY: ['OUT_FOR_DELIVERY'],
  OUT_FOR_DELIVERY: ['DELIVERED'],
  DELIVERED: ['INSTALLATION_SCHEDULED'],
  INSTALLATION_SCHEDULED: ['INSTALLATION_IN_PROGRESS'],
  INSTALLATION_IN_PROGRESS: ['HANDOVER_COMPLETED'],
  HANDOVER_COMPLETED: [],
  CANCELLED: [],
};

async function transitionOrder(orderId: string, toStatus: OrderStatus, actionBy: string) {
  return prisma.$transaction(async (tx) => {
    const order = await tx.order.findUniqueOrThrow({ where: { id: orderId } });

    const allowed = VALID_TRANSITIONS[order.status];
    if (!allowed.includes(toStatus)) {
      throw new DomainRuleError(
        'INVALID_TRANSITION',
        `Cannot transition from ${order.status} to ${toStatus}`
      );
    }

    // Business rule guards
    if (toStatus === 'PRODUCTION_QUEUED') {
      const deposit = await tx.paymentTransaction.findFirst({
        where: { orderId, milestone: 'MILESTONE_1_DEPOSIT', status: 'CAPTURED' },
      });
      if (!deposit) {
        throw new DomainRuleError('NO_DEPOSIT', 'Cannot start production without 50% deposit');
      }
    }

    await tx.order.update({
      where: { id: orderId },
      data: { status: toStatus },
    });

    await tx.orderTimeline.create({
      data: {
        orderId,
        fromStatus: order.status,
        toStatus,
        actionBy,
      },
    });
  });
}
```

## 13. Privacy & Saudi PDPL Compliance

### 13.1 Factory Floor Display Rule

**Models that expose customer PII:** `User`, `CustomerProfile`, `Address`

**Rule:** Factory-floor interfaces (CNC Bridge, cutting lists, QC screens) must NEVER query these models directly. They receive only:
- `BOMItem.barcodeOpaqueToken` (UUID-based, no PII)
- `Order.orderNumber` (business reference, no PII)
- `CuttingJob.id` / `CNCMachineJob.programNumber` (technical IDs)

```typescript
// ✅ Factory floor query — PII-free
const cuttingList = await prisma.cuttingJob.findMany({
  where: { orderId, status: 'NESTED' },
  include: {
    order: { select: { orderNumber: true } },  // Only order number
    materialSheet: { select: { code: true, nameEn: true } },
  },
});

// ❌ NEVER on factory floor
// include: { order: { include: { customer: true } } }
```

### 13.2 Log Redaction

When logging Prisma queries or errors, strip PII fields:

```typescript
const PII_FIELDS = ['phone', 'email', 'fullName', 'nationalIdOrIqamaMasked'];

function redactPII(obj: Record<string, unknown>): Record<string, unknown> {
  const redacted = { ...obj };
  for (const field of PII_FIELDS) {
    if (field in redacted) {
      redacted[field] = '***REDACTED***';
    }
  }
  return redacted;
}
```

## 14. Common Prisma Gotchas & Solutions

### 14.1 "Too Many Connections" in Development

**Cause:** Next.js hot-reload creates new PrismaClient instances.
**Solution:** Always import from `src/lib/prisma.ts` (singleton pattern in Section 3.2).

### 14.2 Decimal Type Mismatch

**Cause:** Prisma returns `Prisma.Decimal` (string-like), not JavaScript `number`.
**Solution:**
```typescript
// Convert before arithmetic
import { toDecimal } from '@/lib/decimal';
const amount = toDecimal(order.grandTotalSar.toString());
// Now safe to use .plus(), .minus(), .times(), .dividedBy()
```

### 14.3 `P2002` Unique Constraint Violation

**Cause:** Trying to create a record with a duplicate unique field.
**Solution:**
```typescript
try {
  await prisma.user.create({ data: { phone: normalizedPhone, ... } });
} catch (error) {
  if (error instanceof Prisma.PrismaClientKnownRequestError && error.code === 'P2002') {
    const target = (error.meta?.target as string[])?.join(', ');
    throw new ConflictError('DUPLICATE', `A record with this ${target} already exists`);
  }
  throw error;
}
```

### 14.4 `P2025` Record Not Found

**Cause:** `update()` or `delete()` targeting a non-existent record.
**Solution:**
```typescript
try {
  await prisma.order.update({ where: { id: orderId }, data: { ... } });
} catch (error) {
  if (error instanceof Prisma.PrismaClientKnownRequestError && error.code === 'P2025') {
    throw new NotFoundError('ORDER_NOT_FOUND', `Order ${orderId} does not exist`);
  }
  throw error;
}
// Or use findUniqueOrThrow() to auto-throw P2025
```

### 14.5 Enum Value Mismatch Between Schema and Code

**Cause:** Adding a new enum value in schema but not regenerating client.
**Solution:**
```bash
# After every schema.prisma change:
npx prisma generate
# TypeScript will then catch invalid enum references at compile time
```

### 14.6 Json Field Typing

**Cause:** Prisma `Json` type maps to `JsonValue` (any). No type safety.
**Solution:** Define TypeScript types and validate at runtime with Zod:
```typescript
// Define the shape
interface FurnitureConfig {
  widthMm: number;
  heightMm: number;
  depthMm: number;
  carcassMaterialCode: string;
  shutterMaterialCode: string;
  options: {
    softClose: boolean;
    lighting: boolean;
    shelves: number;
  };
}

// Validate before writing
const ConfigSchema = z.object({ /* ... */ }) satisfies z.ZodType<FurnitureConfig>;
const validated = ConfigSchema.parse(input);
await prisma.cartItem.create({
  data: {
    configurationJson: validated as unknown as Prisma.JsonObject,
    // ...
  },
});
```

### 14.7 `@updatedAt` Not Updating

**Cause:** Using `$executeRaw` or `$queryRaw` bypasses Prisma's auto-update.
**Solution:** If using raw SQL, manually set the timestamp:
```sql
UPDATE orders SET status = 'CONFIRMED', updated_at = NOW() WHERE id = $1;
```

### 14.8 PowerShell Command Chaining

**Cause:** PowerShell does not support `&&` for chaining commands.
**Solution:** Use semicolons:
```powershell
npx prisma validate; npx prisma generate; npm test
```
